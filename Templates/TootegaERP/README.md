# Templates de geração — TootegaERP

Fonte **versionada** dos templates de geração de ORM usados pelo TootegaERP. O DASE lê os
templates de `.DASE/Templates/` no repositório-alvo; esta pasta é a origem que se copia
para lá, e é aqui que as alterações são revisadas e historiadas.

```
DASE50/Templates/TootegaERP/csharp-efcore/   ← versionado aqui
TootegaERP/.DASE/Templates/csharp-efcore/    ← cópia em uso, lida pelo DASE
```

## Perfil `csharp-efcore`

A estrutura de pastas segue o módulo **VND**, que é a referência do repositório.

| Artefato | Escopo | Saída | Customizável |
|---|---|---|---|
| `Entity.tpl` | tabela `Entity` | `…Infra/Persistencia/Entidades/{Tabela}.Design.cs` | **sim** |
| `DbContext.tpl` | modelo | `…Infra/Persistencia/{Prefixo}DBContext.Design.cs` | **sim** |
| `Configuration.tpl` | tabela `Entity` | `…Infra/Persistencia/Configurations/{Tabela}Configuration.cs` | não |
| `LookupEnum.tpl` | tabela `Lookup` | `…Common/Lookups/{Tabela}.cs` | não |
| `LookupClass.tpl` | tabela `Lookup` | `…Infra/Persistencia/Lookups/{Tabela}.cs` | não |
| `LookupConfiguration.tpl` | tabela `Lookup` | `…Infra/Persistencia/Configurations/{Tabela}Configuration.cs` | não |
| `MirrorEntity.tpl` | tabela espelho | `…Infra/Persistencia/Entidades/Espelho/{Tabela}.cs` | não |
| `MirrorConfiguration.tpl` | tabela espelho | `…Infra/Persistencia/Configurations/{Tabela}EspelhoConfiguration.cs` | não |
| `_Header.tpl` | parcial | cabeçalho `<auto-generated>` | — |

**O sufixo `.Design` marca o que admite customização** — e só a entidade e o DbContext
admitem. Esses dois são `partial`: o gerado fica em `X.Design.cs`, e o que for escrito à mão
vai em `X.cs`, que a geração nunca toca.

Os demais são gerados por inteiro, saem `sealed` e não têm contraparte manual. A
configuration, em particular, é 100% derivada do MER: tudo de que ela precisa — colunas,
índices, defaults, seed, chaves — vem do modelo. Faltando algo, a correção é no modelo.

Espelho segue a mesma regra: campo próprio do módulo sobre entidade alheia muda o esquema,
e esquema começa no MER.

## O que NÃO pode entrar aqui

Nada específico de uma solução — nome de módulo, namespace, caminho absoluto. Esses valores
vivem no `.dsorm` (`Namespace`, `OutputRoot`, `CodeTemplate`), e é o que permite copiar o
perfil inteiro para outro repositório sem editar uma linha.

O **mapa de tipos** também não fica aqui: vive em `.DASE/ORM.Types.json`, no campo
`Mappings["csharp-efcore"]` de cada tipo. Tipo sem mapeamento faz a geração falhar com o
nome do tipo, em vez de emitir código silenciosamente errado.

## Ferramentas

`tools/orm-codegen/` (na raiz do DASE50), rodando sobre o TFX buildado:

```bash
node tools/orm-codegen/gerar.mjs    <MER.dsorm> [--gravar] [--mostrar <trecho>]
node tools/orm-codegen/validar.mjs               # gerado × código em produção
node tools/orm-codegen/importar.mjs  [--gravar]  # traz o código para o MER
```
