# Templates de geração de código

Como criar um perfil de geração — **sem tocar no código do DASE**.

O DASE não sabe gerar C#, Java ou Prisma. Ele lê um modelo `.dsorm`, monta um objeto com o
que o modelo descreve e entrega esse objeto aos seus templates. Todo o conhecimento sobre a
linguagem-alvo, a convenção de pastas e o estilo do código vive nos templates, em arquivos
de texto versionados junto do repositório.

Acrescentar suporte a uma linguagem nova é criar uma pasta.

| Documento | O que traz |
|---|---|
| **[GUIA.md](GUIA.md)** | Passo a passo criando um perfil do zero |
| **[REFERENCIA.md](REFERENCIA.md)** | Sintaxe, filtros e todo o objeto disponível ao template |
| **[TootegaERP/](TootegaERP/)** | Perfil real e completo, C#/EF Core multi-banco |

## Onde os arquivos ficam

```
<repositório-alvo>/
├── .DASE/
│   ├── ORM.Types.json                    tipos + como cada um vira código
│   └── Templates/
│       └── <perfil>/                     um perfil = uma linguagem/framework
│           ├── profile.json              o que gerar e onde
│           ├── Entity.tpl
│           └── ...
└── Modulos/MeuModulo/
    └── MER.dsorm                          o modelo
```

O DASE procura `.DASE/` subindo do `.dsorm` até a raiz do repositório. Os perfis são
**descobertos**: qualquer subpasta de `Templates/` com um `profile.json` vira uma opção.
Não há registro central nem lista para manter.

## Como gerar

Abra o `.dsorm` no designer e chame **Generate ORM Code** (menu de contexto do canvas ou
paleta de comandos). Havendo mais de um perfil e nenhum escolhido no modelo, o DASE
pergunta qual usar.

## As três regras

**1. Nada específico de uma solução dentro do perfil.** Nome de módulo, namespace, caminho
absoluto — nada disso entra nos templates. Esses valores vêm do `.dsorm` e dos projetos
encontrados no disco. É o que permite copiar a pasta do perfil para outro repositório e
gerar de primeira.

**2. Endereçar projetos pelo nome real, nunca por concatenação.** Declare os sufixos em
`ProjectSuffixes` e use `{{ Model.Projects.Infra }}`. Concatenar `{{ Model.Namespace }}.Infra`
funciona até aparecer um projeto fora do padrão ao lado — e aí o código inteiro vai para uma
pasta que não existe.

**3. Arquivo gerado não se edita.** Todo arquivo sai com cabeçalho `<auto-generated>`.

Marque com um sufixo (`.Design.cs` no perfil do TootegaERP) **apenas o que admite
customização** — esse arquivo é `partial`, e o que for escrito à mão vai no arquivo de mesmo
nome sem o sufixo. O que é gerado por inteiro não leva sufixo nenhum: o nome extra só
confundiria, sugerindo uma contraparte manual que não existe.

## O que o DASE garante

- **Determinismo.** Mesmo modelo e mesmos templates produzem byte a byte a mesma saída.
  Não há relógio, aleatoriedade nem ordem de iteração instável. Código gerado vai para o
  controle de versão, e instabilidade aqui poluiria todo commit.
- **Escrita mínima.** Arquivo cujo conteúdo não mudou não é reescrito.
- **Falha cedo.** Tipo sem mapeamento, template ausente ou dois artefatos gravando no mesmo
  caminho interrompem a geração com mensagem — em vez de produzir código silenciosamente errado.
